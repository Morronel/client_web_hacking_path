NeonGraph - Social Network GraphQL API

A cyberpunk social network with a GraphQL API. Probe the schema, exploit the resolvers, own the grid.

Challenges

1 Introspection Recon

The GraphQL API has introspection enabled. Use it to discover hidden types and fields that expose sensitive data.

Hint: Query __schema to map out every type. Some types are not meant to be public.

{__schema{types{name fields{name}}}}

2 Depth Attack

GraphQL queries can be nested deeply through relational fields. There is no depth limit on this API. Overload the server with a deeply nested query (depth > 10).

Hint: Users have posts, posts have authors, authors have posts... After triggering the overload, check the health endpoint.

{users{posts{author{posts{author{posts{author{posts{author{posts{author{username}}}}}}}}}}}

3 Authorization Bypass

The posts query is supposed to filter out private posts. Does it?

Hint: Query all posts and check the isPrivate field. Some content should be restricted.

{posts{title content isPrivate}}

4 GraphQL Injection

The searchUsers query takes a name parameter. The resolver might not sanitize input properly before building its database query.

Hint: Think SQL injection through a GraphQL argument. There's a flags table with interesting columns.

{searchUsers(name:"' UNION SELECT 1,flag_name,flag_value,'x','y' FROM flags--"){username role}}

5 Batch Attack

The API accepts batched queries (JSON array of queries in a single request). There is no rate limiting. Send a batch of more than 5 queries.

Hint: POST a JSON array of query objects to /graphql. Check the extensions field in the response.

[{"query":"{health}"},{"query":"{health}"},{"query":"{health}"},{"query":"{health}"},{"query":"{health}"},{"query":"{health}"}]

6 Field Suggestion Leak

GraphQL error messages are verbose. Misspelling a field name may reveal hidden fields you shouldn't know about.

Hint: Try querying a misspelled field like "secretNot" or "apiKe" and read the error message carefully.

{users{secretNot}}
