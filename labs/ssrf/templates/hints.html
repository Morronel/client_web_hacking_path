Hints

Ch1: Basic Fetch

No Filter

The /fetch?url= endpoint passes your URL directly to urllib.request.urlopen() with zero filtering. The server can reach its own internal endpoints on 127.0.0.1:5008.

Try: /fetch?url=http://127.0.0.1:5008/internal/metadata

Ch2: Blind Webhook

Blind SSRF

The /webhook endpoint fetches your URL server-side but never shows the response body. It does, however, log the status code and response length to a database. Use /check-log to see if internal endpoints responded successfully.

A successful fetch to an internal endpoint (status 200, non-zero length) confirms SSRF.

Ch3: Filtered Fetch

Filter Bypass

The filter blocks the strings 127.0.0.1 and localhost (case-insensitive). But there are many ways to represent the loopback address:

  • Decimal: 2130706433
  • Hex: 0x7f000001
  • IPv6: [::1]
  • Octal: 017700000001
  • Zero: 0.0.0.0

Ch4: Proxy

Protocol Smuggling

The proxy claims to allow only HTTP/HTTPS but only checks the first 4 characters of the URL. Python's urllib supports file:// URIs. A flag file lives at /app/flag.txt.

Try: /proxy?url=file:///app/flag.txt

Ch5: Redirect Fetch

Redirect Bypass

The endpoint blocks localhost in the initial URL but follows HTTP 302 redirects. The app has a /redirect-to?url= helper. Host a redirect or use a service that 302s to the internal target.

Chain: external URL → 302 → http://127.0.0.1:5008/internal/db-backup

Ch6: DNS-Checked Fetch

DNS Rebinding / TOCTOU

The server resolves the hostname and blocks if it falls in 127.0.0.0/8. But the check and the actual fetch are two separate DNS lookups (TOCTOU). Also, 0.0.0.0 does not match 127.x.x.x but still reaches the local machine on many systems.

Try http://0.0.0.0:5008/internal/metadata — it resolves to 0.0.0.0, not 127.*.
