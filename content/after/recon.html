Web Reconnaissance & Bug Bounty

Passive Reconnaissance

Passive recon gathers information about a target without directly interacting with their systems. This makes it undetectable and is always the first phase of any security assessment.

WHOIS Lookups

WHOIS records reveal domain registration details including the registrant organization, registration date, name servers, and sometimes contact information. Use whois example.com or online tools.

DNS Records

DNS records map the target's infrastructure. Key record types:

RecordPurposeSecurity Relevance
A / AAAAMaps domain to IPReveals hosting provider, co-hosted sites
MXMail serverEmail infrastructure, potential phishing targets
TXTVerification, SPF, DKIMMay reveal third-party services
CNAMEAlias to another domainSubdomain takeover opportunities
NSName serversDNS provider, zone transfer potential

Wayback Machine

The Internet Archive's Wayback Machine (web.archive.org) stores historical snapshots of websites. Old versions may expose endpoints, credentials in JavaScript files, or deprecated functionality that is still accessible on the live site.

Google Dorks

Google dorking uses advanced search operators to find sensitive information indexed by Google: 

site:example.com filetype:pdf          — PDF files on the target
site:example.com inurl:admin            — Admin pages
site:example.com intitle:"index of"     — Directory listings
site:example.com ext:sql | ext:env      — Database dumps or env files
inurl:"/wp-content/debug.log"           — WordPress debug logs

Certificate Transparency

Certificate Transparency (CT) logs record every SSL/TLS certificate issued. Tools like crt.sh let you search CT logs to discover subdomains that have had certificates issued, even if they are not publicly linked anywhere.

Active Reconnaissance

Active recon involves directly interacting with the target. This is detectable and should only be performed within authorized scope.

Subdomain Enumeration

Discovering subdomains reveals the target's attack surface. Techniques include DNS brute-forcing (trying common subdomain names), scraping search engine results, and querying CT logs. Tools: subfinder, amass, knockpy.

Directory Brute-Forcing

Discovering hidden paths and files on a web server by testing common file and directory names. Tools: gobuster, feroxbuster, dirsearch.

Technology Fingerprinting

Identifying the technologies running on a target (web server, framework, CMS, JavaScript libraries) helps narrow down potential vulnerabilities. Tools: Wappalyzer, WhatWeb, BuiltWith.

Bug Bounty Methodology

Scope Analysis

Always start by carefully reading the program's scope. Understand which domains, subdomains, and vulnerability types are in scope. Out-of-scope testing can result in legal consequences and program bans.

Target Prioritization

Focus your efforts on the highest-value targets:

  • Newly added scope — less likely to have been tested by others
  • Older/legacy applications — may have weaker security controls
  • User input-heavy features — search, forms, file uploads, APIs
  • Authentication and authorization flows — login, password reset, role-based access
  • Third-party integrations — often overlooked in security reviews
Bug bounty tip: The best bug bounty hunters do not just run automated scanners. They understand the application's business logic and look for flaws in how features interact. Manual testing with a deep understanding of the application almost always yields higher-impact findings.
Legal reminder: Only perform reconnaissance against targets where you have explicit authorization. Bug bounty programs define what is in scope — respect those boundaries.
