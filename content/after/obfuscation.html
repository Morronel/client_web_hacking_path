Obfuscation & WAF Evasion

What Are WAFs?

A Web Application Firewall (WAF) is a security layer that sits between users and a web application, inspecting HTTP traffic and blocking requests that match known attack patterns. WAFs are deployed by organizations to add a layer of defense against common web attacks like SQL injection, XSS, and command injection.

Popular WAFs include Cloudflare, AWS WAF, ModSecurity, Imperva, and Akamai. While they are valuable defensive tools, they are not a substitute for writing secure code.

Signature-Based Detection

Most WAFs rely heavily on signature-based detection — they maintain a database of patterns (regular expressions, string matches) that correspond to known attack payloads. When an incoming request matches a signature, the WAF blocks it. 

Example WAF rules (simplified):
  Block if request contains: <script
  Block if request contains: ' OR 1=1
  Block if request contains: UNION SELECT
  Block if request contains: /etc/passwd

The fundamental weakness of signature-based detection is that it can only catch what it knows about. By transforming a payload's syntax without changing its semantics, an attacker can evade the signatures.

Common Evasion Techniques

1. Case Variation

Many filters match specific cases. Since HTML and SQL are largely case-insensitive, mixing case can bypass naive filters: 

Blocked:  <script>alert(1)</script>
Bypass:   <ScRiPt>alert(1)</ScRiPt>

Blocked:  UNION SELECT
Bypass:   uNiOn SeLeCt

2. URL Encoding

Encode characters as their percent-encoded equivalents. If the WAF checks before the server decodes, the payload slips through: 

Blocked:  <script>
Encoded:  %3Cscript%3E

3. HTML Entity Encoding

Within HTML contexts, entity-encoded characters are decoded by the browser: 

Blocked:  <img src=x onerror=alert(1)>
Encoded:  <img src=x onerror=alert(1)>

4. SQL Comment Insertion

SQL allows inline comments (/*...*/) anywhere whitespace is valid. Inserting comments breaks up keywords that WAFs look for: 

Blocked:  UNION SELECT * FROM users
Bypass:   UN/**/ION SEL/**/ECT * FROM users

5. Double Encoding

If a WAF decodes once and then passes the request to an application that decodes again, double encoding can bypass the filter: 

Original:        <
Single encoded:  %3C
Double encoded:  %253C  (the % is encoded as %25)

6. Unicode Normalization

Some applications normalize Unicode characters to their ASCII equivalents after the WAF inspects them. Using Unicode look-alikes can bypass filters: 

Normal:    <script>
Unicode:   ＜script＞  (using fullwidth characters)
Ethical context: WAF evasion techniques should only be used during authorized penetration testing or bug bounty programs where you have explicit permission. Using these techniques against systems you do not own or have authorization to test is illegal and unethical.
Defense perspective: Understanding evasion techniques is crucial for building better defenses. Developers should not rely on WAFs alone — always validate and sanitize input at the application level, use parameterized queries, and implement Content Security Policy.
