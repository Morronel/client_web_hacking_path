Module 08 — Lab Setup

Before You Start Hacking: Setting Up Your Environment

The vulnerability modules in this course come with real, vulnerable web applications that you can hack locally on your own machine. Each lab is a Flask (Python) app packaged in a Docker container. This module walks you through installing everything you need.

What you'll install: Git (to clone the repository) and Docker + Docker Compose (to run the labs). That's it. No Python setup needed — Docker handles everything.

Step 1: Install Git

Git is a version control tool. You need it to download (clone) the course repository.

Windows

Download and install Git for Windows from https://git-scm.com/download/win. Run the installer with default options. After installation, open Git Bash or PowerShell and verify:

git --version
# Should output something like: git version 2.43.0

macOS

Git comes with Xcode Command Line Tools. Open Terminal and run:

xcode-select --install
# Or install via Homebrew:
brew install git

git --version

Linux (Ubuntu/Debian)

sudo apt update && sudo apt install git -y
git --version

Step 2: Install Docker & Docker Compose

Docker runs each lab in an isolated container — like a tiny virtual machine. Docker Compose makes it easy to build and start these containers with a single command.

Windows & macOS

Install Docker Desktop from https://www.docker.com/products/docker-desktop/. Docker Desktop includes both Docker and Docker Compose. After installation, make sure Docker Desktop is running (you'll see a whale icon in your system tray).

docker --version
# Should output: Docker version 24.x or newer

docker compose version
# Should output: Docker Compose version v2.x

Linux (Ubuntu/Debian)

# Install Docker
curl -fsSL https://get.docker.com | sh

# Add your user to the docker group (so you don't need sudo)
sudo usermod -aG docker $USER

# Log out and back in, then verify:
docker --version
docker compose version

If docker compose isn't found, you may need to install the Compose plugin separately:

sudo apt install docker-compose-plugin
Common issue: If you get "permission denied" when running Docker commands on Linux, make sure you've added your user to the docker group and logged out/back in. Or prefix commands with sudo.

Step 3: Clone the Repository

Open a terminal and clone the WebHack Academy repository: 

git clone https://github.com/morronel/client_web_hacking_path.git
cd client_web_hacking_path

This downloads the entire course including all lab source code. The labs live in the labs/ directory: 

ls labs/
# sqli/  xss/  ssti/  idor/  auth/  csrf/  ssrf/  traversal/
# upload/  cmdi/  xxe/  race/  deserial/  graphql/

Step 4: Start a Lab

Each lab is a self-contained Docker container. To start one: 

# Navigate to a lab directory
cd labs/sqli

# Build and start the container
docker compose up --build

# The lab is now running! Visit it in your browser:
# http://localhost:5001

Press Ctrl+C to stop the lab when you're done.

Tip: Add -d to run in the background: docker compose up --build -d. Then use docker compose down to stop it.

Useful Tools

While you can solve most challenges with just a browser and curl, these tools make your life easier:

  • curl — Command-line HTTP client (comes with Linux/Mac, install via Git Bash on Windows)
  • Burp Suite Community — Intercepts and modifies HTTP requests between your browser and the lab
  • Browser DevTools (F12) — Network tab, Console, and Application tab for cookies
  • webhook.site — Free service that gives you a URL to receive HTTP callbacks (useful for XSS cookie theft and SSRF testing)
  • Python 3 — For writing exploit scripts (blind SQLi automation, pickle payload generation, etc.)

Troubleshooting

"Cannot connect to the Docker daemon"

Make sure Docker Desktop is running (Windows/Mac) or the Docker service is started (Linux):

# Linux
sudo systemctl start docker

"Port already in use"

Another lab (or application) is using that port. Stop it first:

docker compose down   # in the other lab's directory
# Or stop all containers:
docker stop $(docker ps -q)

"Build fails" or "pip install fails"

The labs use pre-built wheel files for offline installation, so network issues during build shouldn't be a problem. If a build fails, try:

docker compose build --no-cache
You're ready! Once Git and Docker are installed, head to the first vulnerability module (SQL Injection) and start hacking. Each module's page has the specific docker compose command to start its lab.
