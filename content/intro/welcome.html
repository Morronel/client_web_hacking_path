Module 00 — Welcome to WebHack Academy

So You Want to Hack Websites?

Cool. You're in the right place.

But first, let's get something straight: hacking isn't what Hollywood thinks it is. There's no green text raining down your screen while you furiously type HACK THE MAINFRAME and a progress bar fills up. Sorry to disappoint.

Real hacking is more like... being a really curious detective who speaks computer. You look at a website and wonder: "What happens if I put something weird in this search box? What if I change this number in the URL? What if I send a request the developers never expected?"

And sometimes — often, actually — the answer is: something the developers REALLY didn't want to happen.

The Hacker Mindset: A hacker doesn't look at a login page and think "I should type my username and password." A hacker looks at a login page and thinks "I wonder what this does if I type a single quote character..."

What Even IS Web Hacking?

Every time you open a website, your browser is having a conversation with a server somewhere in the world. Your browser says "Hey, give me the homepage!" and the server says "Sure, here's some HTML, CSS, and JavaScript." Then your browser says "The user just clicked Login, here's their username and password" and the server says "Cool, they're legit, here's a cookie to prove it."

Web hacking is the art of messing with that conversation. What if you change the message before it gets to the server? What if you forge the cookie? What if you trick the server into thinking you're the admin? What if you make the server read files it shouldn't, or run commands you're not supposed to run?

That's what this course teaches you. Not so you can go break stuff (that's illegal and also not cool), but so you can understand how things break — and then learn how to fix them.

Why Should You Care?

Here's a fun fact that will either excite you or terrify you (probably both):

  • In 2023, the average cost of a data breach was $4.45 million. That's not a typo. Four and a half million dollars. Every time someone finds a SQL injection in a banking app and decides to be a jerk about it, somebody somewhere is having a VERY bad day.
  • There were over 2,300 publicly disclosed data breaches in 2023. That's more than 6 per day. And those are just the ones we know about.
  • Bug bounty hunters earned over $45 million in 2023 through platforms like HackerOne and Bugcrowd. That's people getting paid — legally, by companies who asked for help — to find exactly the vulnerabilities you'll learn about here.
  • The cybersecurity industry has over 3.5 million unfilled jobs worldwide. There literally aren't enough people who know this stuff.

So whether you want to be a security researcher, a penetration tester, a bug bounty hunter, a developer who writes secure code, or just someone who understands how the internet actually works under the hood — you're investing your time wisely.

How This Course Works

WebHack Academy is split into three sections, like a really satisfying sandwich:

🍞 Section 1: Introduction (Modules 01-07)

The bread. The foundation. Before you can exploit anything, you need to understand how the web works. We'll cover the legal stuff (so you don't go to jail — kind of important), networking basics (HTTP, DNS, how your browser talks to servers), encoding (Base64, URL encoding, the stuff that makes URLs look weird), cookies and sessions (how websites remember who you are), the Same-Origin Policy (the browser's bouncer), the history of hacking (it's wild), and the Cyber Kill Chain (how real attacks happen, step by step).

This section might seem boring compared to the "actual hacking" part, but trust me — every single exploit you'll ever write relies on understanding these fundamentals. The best hackers in the world don't memorize payloads. They understand protocols.

🥩 Section 2: Vulnerabilities (Modules 08-22)

The meat. The good stuff. Fifteen different types of web vulnerabilities, each with:

  • Theory — What is this vulnerability? Why does it exist? How does the code go wrong?
  • Examples — Real-world code (vulnerable AND safe versions) so you can see exactly what's happening
  • Quizzes — Test yourself before you wreck yourself
  • Flask Labs — Actual vulnerable web applications running in Docker containers that you can hack for real. Each lab has hidden flags (like FLAG{...}) that you need to find by exploiting the vulnerabilities.

We'll cover the OWASP Top 10 classics — SQL Injection, XSS, CSRF — plus cool stuff like Race Conditions, Deserialization attacks, and GraphQL hacking. By the end, you'll look at websites differently. You'll notice things. You'll see attack surfaces everywhere. (This is both a blessing and a curse. You've been warned.)

🍞 Section 3: Aftermath (Modules 23-26)

The other piece of bread. What happens AFTER you find a vulnerability? How do you report it responsibly? How do attackers try to hide their exploits from Web Application Firewalls (WAFs)? How do you do reconnaissance to find targets (legally, through bug bounty programs)? And where do you go from here?

Plus: Shadow Terminal — Complete enough modules and you'll unlock a bonus card game built right into the platform. Because learning should be fun, and sometimes you need a break from staring at SQL queries.

What You'll Need

Not much, honestly:

  • A web browser — Chrome, Firefox, whatever. You'll want to learn the Developer Tools (F12). This is your most important hacking tool, and it's already installed on your computer.
  • Docker — For running the Flask labs. Each lab is a self-contained Docker container you start with docker compose up --build.
  • curl or a tool like Burp Suite — For sending custom HTTP requests. curl comes with every Linux and Mac. Burp Suite Community Edition is free and incredible.
  • Curiosity — The most important tool of all. Every great hacker started by asking "what happens if I..."

The Golden Rules

Before we dive in, three rules you should tattoo on the inside of your eyelids:

Rule 1: Never Hack Without Permission

This is not optional. This is not a suggestion. This is the difference between a career and a criminal record. The labs in this course are designed to be hacked — that's the whole point. Real websites are not. Unless you have explicit, written permission (through a bug bounty program, a pentest contract, or you own the system), don't touch it.

"But I was just testing!" is not a legal defense. Ask the many people who've learned this the hard way.

Rule 2: Understand Before You Exploit

Copy-pasting payloads from the internet without understanding them makes you a script kiddie, not a hacker. The goal of this course isn't to memorize ' OR 1=1--. It's to understand why that works, when it works, when it won't work, and how to find the right approach when the standard payloads fail.

Real-world applications don't have a big "Vulnerable Input Field" sign. You need to think.

Rule 3: Always Be Learning

Security is a moving target. New vulnerabilities are discovered every day. New defenses are built. New bypasses are found for those defenses. The best hackers never stop learning. Follow security researchers on Twitter/X, read writeups on HackerOne and Medium, participate in CTF competitions, and keep building things so you understand how they break.

A Quick Word About CTF Flags

Throughout the Flask labs, you'll find hidden "flags" — strings that look like FLAG{some_leetspeak_text}. These come from CTF (Capture The Flag) competitions, which are basically hacking competitions where teams race to find vulnerabilities and extract these flag strings.

Finding a flag proves you successfully exploited the vulnerability. It's like a receipt that says "yes, I actually did the hack, I didn't just read the walkthrough." (Though there's no shame in reading walkthroughs when you're learning — that's literally how everyone starts.)

Before You Start: The Hacker's Toolkit

Here are the tools you'll use throughout this course. Don't worry about mastering them all right now — we'll introduce them as we go.

Browser Developer Tools (F12)

Your #1 tool. Every browser has built-in developer tools that let you inspect HTML, watch network requests, modify cookies, run JavaScript in the console, and much more. If you've never opened DevTools before, do it now: press F12 (or Ctrl+Shift+I on Chrome/Firefox). Click around. Break things. That's the spirit.

Key tabs you'll use:

  • Elements/Inspector — See and edit the HTML of any page in real-time
  • Console — Run JavaScript commands (great for XSS testing)
  • Network — Watch every HTTP request your browser makes (this is where the magic happens)
  • Application/Storage — View and modify cookies, localStorage, sessionStorage

curl

A command-line tool for sending HTTP requests. It comes pre-installed on Linux and Mac. Think of it as a browser that you control with typed commands instead of clicking. You can set any header, send any body, use any HTTP method. It's like texting the server directly instead of going through the browser's UI. 

# GET request
curl http://localhost:5001/

# POST request with form data
curl -X POST http://localhost:5001/login -d "username=admin&password=test"

# POST with JSON body
curl -X POST http://localhost:5001/api -H "Content-Type: application/json" -d '{"key":"value"}'

# See response headers
curl -I http://localhost:5001/

# Send a cookie
curl -b "session=abc123" http://localhost:5001/dashboard

Burp Suite (Community Edition)

The Swiss Army knife of web hacking. Burp Suite sits between your browser and the server as a proxy, letting you intercept, inspect, and modify every HTTP request before it reaches the server. The Community Edition is free and has everything you need for learning.

Key features: Proxy (intercept requests), Repeater (resend modified requests), Intruder (automated fuzzing), Decoder (encode/decode Base64, URL, etc.).

Docker

Docker runs the Flask labs. Each lab is a self-contained "container" — like a tiny virtual computer running a vulnerable web application. You start a lab with: 

cd labs/sqli              # navigate to the lab folder
docker compose up --build  # build and start the container
# Visit http://localhost:5001 in your browser
# Press Ctrl+C to stop when done

Containers are isolated, so you can break things without affecting your real system. That's the beauty of Docker — it's a safe playground.

One Last Thing...

Learning security is a journey, not a destination. You're going to feel confused sometimes. You're going to stare at a payload and wonder why it doesn't work. You're going to read about a vulnerability and think "there's NO way real websites are this broken" (they are). And then one day, something will click, and you'll see the Matrix.

Okay, maybe not the Matrix. But you'll understand something fundamental about how software works — and how it fails. And that understanding is genuinely valuable, whether you're building, breaking, or defending.
