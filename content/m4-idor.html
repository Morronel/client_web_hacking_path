Module 4: Insecure Direct Object Reference

Learn how broken access controls allow attackers to access unauthorized data by manipulating object identifiers.

Authorization vs Authentication

Authentication verifies who you are (login credentials). Authorization determines what you can access (permissions). IDOR is an authorization failure — the app knows who you are but doesn't check if you're allowed to access a specific resource.

What is IDOR?

Insecure Direct Object Reference occurs when an application uses user-supplied input to directly access objects (database records, files, etc.) without verifying the user is authorized to access that specific object.

# Vulnerable endpoint — no authorization check
@app.route('/api/user/<id>')
def get_user(id):
    return db.query("SELECT * FROM users WHERE id = ?", id)

# Safe endpoint — checks authorization
@app.route('/api/user/<id>')
@login_required
def get_user(id):
    if current_user.id != id and not current_user.is_admin:
        return {"error": "Forbidden"}, 403
    return db.query("SELECT * FROM users WHERE id = ?", id)

Horizontal vs Vertical Privilege Escalation

  • Horizontal: Accessing another user's data at the same privilege level (user A reads user B's profile)
  • Vertical: Accessing resources requiring higher privileges (regular user accesses admin panel)

Where IDORs Appear

  • URL parameters: /api/user/123, /invoice?id=456
  • POST body: {"userId": 123, "action": "delete"}
  • API responses: IDs leaked in responses enable further enumeration
  • Headers: Custom headers like X-User-Id
  • Cookies: User ID embedded in session cookies

Predictable Identifiers

  • Sequential integers: 1, 2, 3... — easiest to enumerate
  • Encoded IDs: Base64-encoded integers — security through obscurity
  • UUIDs: Harder to guess but still vulnerable if leaked

Testing Methodology

  1. Identify all endpoints that reference objects by ID
  2. Note your own valid IDs from legitimate requests
  3. Modify the ID parameter to another value (increment, decrement, etc.)
  4. Observe if the application returns data for the modified ID
  5. Check both the response body and status codes
Real-world impact: IDOR vulnerabilities have led to massive data breaches. In 2019, a major airline exposed 9 million customer records through an IDOR in their API. Always implement server-side authorization checks.
