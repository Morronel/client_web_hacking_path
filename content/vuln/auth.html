Module 12 — Broken Authentication & Username Enumeration

Discover how poor authentication implementations leak information and enable credential attacks.

Authentication Flaws

Authentication is the process of verifying identity. Common flaws include:

  • Verbose error messages — revealing whether a username exists
  • No rate limiting — allowing unlimited login attempts
  • Weak password policies — accepting easily guessable passwords
  • Insecure credential storage — plaintext or weak hashing
  • Missing MFA — single factor authentication only

Username Enumeration

When an application responds differently for valid vs invalid usernames, attackers can enumerate valid accounts:

ScenarioValid UsernameInvalid Username
Error message"Incorrect password""User not found"
Response time~500ms (password hashed)~50ms (quick reject)
Account lockoutAccount locked after 5 triesNo lockout behavior
HTTP status401 Unauthorized404 Not Found
Correct implementation: Always return a generic message like "Invalid username or password" regardless of which field is wrong. Use constant-time comparison for credentials.

Credential Attack Types

  • Brute force: Try all possible passwords for one account
  • Credential stuffing: Use leaked username/password pairs from other breaches
  • Password spraying: Try a few common passwords against many accounts

Top 20 Weak Passwords

These are consistently found in breach databases year after year:

123456 password 123456789 12345678 12345 1234567 1234567890 qwerty abc123 111111 password1 iloveyou 1q2w3e4r 000000 letmein welcome monkey dragon master admin

Defenses

  • Uniform error messages: Same response for all login failures
  • Rate limiting: Lock accounts or add delays after failed attempts
  • CAPTCHA: After several failed attempts
  • MFA: Require a second authentication factor
  • Constant-time comparison: Prevent timing side-channels
