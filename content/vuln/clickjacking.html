Module 14 — Clickjacking

Learn how UI redress attacks trick users into clicking hidden elements by layering transparent iframes over decoy pages.

What is Clickjacking?

Clickjacking (UI redress) is an attack where a malicious page embeds a target application in a transparent or obscured <iframe>. The attacker positions the iframe so that when the victim clicks on what appears to be a harmless element (a button, a game), they are actually clicking on a sensitive control in the hidden target page — such as "Delete Account" or "Transfer Funds."

Attack Technique

<!-- Attacker's page: invisible iframe over a decoy button -->
<style>
  iframe {
    position: absolute;
    top: 0; left: 0;
    width: 500px; height: 300px;
    opacity: 0.0001;  /* nearly invisible */
    z-index: 10;
  }
  .decoy-btn {
    position: absolute;
    top: 120px; left: 50px;
    z-index: 1;
  }
</style>
<div class="decoy-btn">Click here to win a prize!</div>
<iframe src="https://bank.com/settings?action=delete"></iframe>

The victim sees only the "win a prize" button but their click lands on the iframe, triggering the delete action on bank.com where they are already authenticated.

Vulnerable Code: No Frame Protection

# Flask — VULNERABLE: no framing protection headers
@app.route('/settings')
@login_required
def settings():
    return render_template('settings.html')

Safe Code: Frame Protection Headers

# Flask — SAFE: X-Frame-Options and CSP frame-ancestors
@app.after_request
def add_security_headers(response):
    response.headers['X-Frame-Options'] = 'DENY'
    response.headers['Content-Security-Policy'] = "frame-ancestors 'none'"
    return response

Defense Mechanisms

X-Frame-Options Header

This response header controls whether the page can be embedded in frames:

  • DENY: Page cannot be displayed in any frame.
  • SAMEORIGIN: Page can only be framed by pages on the same origin.
  • ALLOW-FROM uri: Deprecated; only supported by older browsers.

CSP frame-ancestors

The frame-ancestors directive in Content-Security-Policy supersedes X-Frame-Options and provides more granular control: 

Content-Security-Policy: frame-ancestors 'self' https://trusted-partner.com

Unlike X-Frame-Options, frame-ancestors supports multiple origins and wildcards.

JavaScript Frame-Busting (and Its Limitations)

// Classic frame-busting script
if (top !== self) {
    top.location = self.location;
}

Frame-busting scripts attempt to break out of iframes, but they can be bypassed in several ways:

  • sandbox attribute: <iframe sandbox="allow-forms"> blocks scripts from navigating the parent.
  • Double framing: Nesting frames can confuse top !== self checks.
  • onbeforeunload: The attacker can cancel the navigation attempt.
Do not rely on JavaScript alone. Frame-busting scripts are easily defeated. Always use server-side headers (X-Frame-Options and CSP frame-ancestors) as the primary defense.
Clickjacking Impact: One-click account deletion, unauthorized purchases, enabling webcam/microphone (via permission dialogs), changing security settings, liking/sharing content on social media, and downloading malware.
