Module 20 — Race Conditions

Explore how TOCTOU (Time-of-Check to Time-of-Use) flaws allow attackers to exploit timing gaps in concurrent operations.

What Are Race Conditions?

Race conditions occur when two or more operations on shared state happen concurrently without proper synchronization. In web apps, this typically manifests as a TOCTOU vulnerability: the server checks a condition (e.g., "does the user have enough balance?"), then acts on it (e.g., "deduct balance"), but the gap between check and action allows concurrent requests to all pass the check.

The TOCTOU Pattern

Vulnerable Code

@app.route('/redeem', methods=['POST'])
def redeem():
    code = request.form['code']
    voucher = db.execute(
        'SELECT * FROM vouchers WHERE code=? AND redeemed=0', (code,)
    ).fetchone()

    if not voucher:
        return 'Invalid or already redeemed'

    # TOCTOU GAP: another request can pass the check above
    # before this update executes
    time.sleep(0.1)  # Network latency / DB delay widens the window

    db.execute('UPDATE vouchers SET redeemed=1 WHERE code=?', (code,))
    db.execute('UPDATE accounts SET balance=balance+? WHERE id=?',
               (voucher['value'], user_id))
    db.commit()
    return 'Voucher redeemed!'

Safe Code

@app.route('/redeem', methods=['POST'])
def redeem():
    code = request.form['code']
    # SAFE: atomic update — check and modify in single query
    result = db.execute(
        'UPDATE vouchers SET redeemed=1 WHERE code=? AND redeemed=0', (code,)
    )
    if result.rowcount == 0:
        return 'Invalid or already redeemed'

    db.execute('UPDATE accounts SET balance=balance+? WHERE id=?',
               (voucher_value, user_id))
    db.commit()
    return 'Voucher redeemed!'

Real-World Examples

  • Double-spend: Redeem the same gift card/voucher multiple times
  • Overdraft: Withdraw more money than account balance by racing withdrawals
  • Duplicate registration: Create multiple accounts with "unique" username
  • Like/vote inflation: "Like" a post hundreds of times before the check catches up

Exploitation Technique

# Send 20 concurrent requests using curl + xargs
seq 20 | xargs -P20 -I{} curl -sX POST http://localhost:5013/redeem \
  -d "code=GIFT-CARD-123"

# Or with Python threading
import threading, requests
def redeem():
    requests.post('http://localhost:5013/redeem', data={'code': 'GIFT-CARD-123'})
threads = [threading.Thread(target=redeem) for _ in range(20)]
for t in threads: t.start()
for t in threads: t.join()

Prevention

  • Atomic operations: Use UPDATE ... WHERE condition to check and modify in one query
  • Database transactions: Use SELECT ... FOR UPDATE to lock rows
  • Optimistic locking: Use version columns to detect concurrent modifications
  • Idempotency keys: Assign unique IDs to operations to detect duplicates
Impact: Race conditions can cause financial loss (double-spend), data corruption, privilege escalation, and bypass of security checks. They are notoriously difficult to detect with automated scanning.
