Module 22 — GraphQL Vulnerabilities

Learn how GraphQL APIs introduce unique attack surfaces including introspection leaks, depth attacks, injection, and authorization bypasses.

GraphQL Basics

GraphQL is a query language for APIs that lets clients specify exactly what data they need. Unlike REST, it uses a single endpoint and a typed schema. While powerful, it introduces security challenges not present in traditional REST APIs.

# Basic query
{
  users {
    id
    username
    email
  }
}

# Mutation
mutation {
  createPost(title: "Hello", content: "World") {
    id
  }
}

Attack Vectors

1. Introspection

GraphQL allows clients to query the full schema, revealing all types, fields, and relationships — including hidden or admin-only types:

{
  __schema {
    types {
      name
      fields { name type { name } }
    }
  }
}

2. Nested Query / Depth Attack

Without depth limiting, recursive relationships allow exponentially expensive queries:

{
  users {
    posts {
      author {
        posts {
          author {
            posts { ... } # infinite nesting
          }
        }
      }
    }
  }
}

3. Authorization Bypass

GraphQL resolvers must enforce per-field authorization. A common mistake is securing the mutation but not the query, or protecting a resource at one query path but not another:

# DANGEROUS: no auth check in resolver
def resolve_posts(root, info):
    return db.execute('SELECT * FROM posts').fetchall()
    # Returns ALL posts, including private ones!

4. Injection in Resolvers

# DANGEROUS: string interpolation in SQL
def resolve_search_users(root, info, name):
    return db.execute(f"SELECT * FROM users WHERE name LIKE '%{name}%'").fetchall()
    # SQL injection via GraphQL argument!

5. Batching Attacks

Many GraphQL servers accept arrays of queries in a single request, bypassing rate limiters that count HTTP requests rather than query operations.

6. Field Suggestion Information Disclosure

When a field name is misspelled, error messages may suggest valid field names, leaking schema information even when introspection is disabled.

Prevention

  • Disable introspection in production
  • Implement query depth limiting (max depth 5-10)
  • Per-field authorization in every resolver
  • Parameterized queries in resolvers (never string interpolation)
  • Query cost analysis to prevent expensive operations
  • Batch size limits on array queries
Impact: GraphQL vulnerabilities can leak entire database schemas, expose private data, enable DoS through expensive queries, and serve as injection vectors. The single-endpoint nature means traditional WAF rules often miss these attacks.
