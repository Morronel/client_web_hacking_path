Модуль 19 — Path Traversal

Дізнайся, як атакуючі виходять за межі дозволених директорій, щоб читати довільні файли на сервері.

Втеча з пісочниці

Path traversal — це красиво у своїй простоті. Додаток віддає файли з певної директорії — скажімо, /app/documents/public/. Користувачі запитують файли за назвою: /view?file=report.pdf. Сервер конкатенує ім'я файлу до базового шляху і відкриває файл. Просто, так?

А що станеться, коли користувач запросить /view?file=../../../etc/passwd? Сервер побудує шлях /app/documents/public/../../../etc/passwd. Операційна система обробить послідовності ../, піднімаючись на три рівні директорій вгору, і опиниться на /etc/passwd. Атакуючий щойно прочитав файл, до якого ніколи не повинен був мати доступ.

Це і є path traversal (також відомий як directory traversal або dot-dot-slash атаки). Він експлуатує простий факт: ../ означає "піднятися на одну директорію вгору" у будь-якій операційній системі, і багато додатків не перевіряють, що підсумковий шлях залишається в межах дозволеної директорії.

Вразливий патерн

Вразливий код

@app.route('/view')
def view():
    filename = request.args.get('file')
    # DANGEROUS: user controls the filename, can use ../ to escape
    with open(f'documents/public/{filename}') as f:
        return f.read()

# Normal:  /view?file=report.pdf  → opens documents/public/report.pdf
# Attack:  /view?file=../../../etc/passwd → opens /etc/passwd

Безпечний код

import os

@app.route('/view')
def view():
    filename = request.args.get('file')
    # Step 1: Strip any path components — only keep the filename
    safe_name = os.path.basename(filename)
    # Step 2: Construct the full path
    full_path = os.path.join('documents/public', safe_name)
    # Step 3: Resolve symlinks and verify the path is still within bounds
    real_path = os.path.realpath(full_path)
    if not real_path.startswith(os.path.realpath('documents/public')):
        abort(403)
    with open(real_path) as f:
        return f.read()

Безпечна версія робить три речі: (1) os.path.basename() відкидає всі компоненти шляху — ../../../etc/passwd стає просто passwd. (2) os.path.realpath() резолвить будь-які символічні посилання або залишкові послідовності ../. (3) Перевірка startswith() підтверджує, що фінальний шлях все ще знаходиться в дозволеній директорії.

Техніки обходу traversal-фільтрів

Розробники часто намагаються блокувати ../ простою заміною рядка. Це майже завжди можна обійти:

ПейлоадЯк це працюєЩо обходить
../Базовий підйом на рівень вгоруБез фільтрів
....//Після одноразового видалення ../ стає ../Однопрохідна заміна рядка
..././Той самий трюк, інше розташуванняОднопрохідна заміна
%2e%2e%2fURL-закодований ../Валідація до URL-декодування
..%252fПодвійне URL-кодування (%25 = %)Одноразове декодування + перевірка
%00Null byte — обрізає рядок у C-мовахДодавання розширення (.pdf)
..\/Зворотний слеш — Windows трактує і /, і \ як роздільникиФільтри, що перевіряють лише /
..%5cURL-закодований зворотний слешWindows + URL-декодування
Трюк з Null Byte: У старіших версіях PHP, Java та інших рантаймах на базі C, null byte (%00) обрізав рядок. Тобто якщо сервер додає .pdf до імені файлу: ../../../etc/passwd%00.pdf → ОС бачить ../../../etc/passwd (null byte відрізає решту). Сучасні рантайми це здебільшого виправили, але трюк все ще зустрічається у CTF та старих системах.

Цільові файли високої цінності

Коли ти підтвердив path traversal, ось файли, за якими варто йти:

# === Linux ===
/etc/passwd              # User accounts (always readable, confirms traversal)
/etc/shadow              # Password hashes (requires root)
/proc/self/environ       # Environment variables — often contains API keys, secrets
/proc/self/cmdline       # How the process was started
/app/.env                # Application secrets (DB credentials, API keys)
/app/config/database.yml # Rails database config
~/.ssh/id_rsa            # SSH private key
~/.bash_history          # Command history

# === Windows ===
C:\Windows\win.ini       # Always exists, confirms traversal
C:\Windows\system.ini
C:\inetpub\wwwroot\web.config   # IIS configuration with connection strings
C:\Users\Administrator\.ssh\id_rsa
Порада профі: /proc/self/environ — це золота жила на Linux. Він містить усі змінні оточення поточного процесу, які в сучасних деплоях часто включають паролі баз даних, API-ключі, JWT-секрети та хмарні креденшали. Якщо ти можеш прочитати цей файл, у тебе, ймовірно, достатньо для повної компрометації додатка.

Path Traversal за межами читання файлів

Читання файлів — це найпоширеніший вплив, але path traversal може бути ще небезпечнішим у поєднанні з іншими функціями:

  • Запис файлів + traversal: якщо додаток дозволяє завантажувати/записувати файли і має вразливість traversal, ти можеш записати вебшелл у кореневу директорію веб-сервера
  • Отруєння логів: впровадь PHP-код у лог-файл через спеціально сформований заголовок User-Agent, потім використай traversal для підключення лог-файлу через вразливість Local File Inclusion (LFI)
  • Розкриття вихідного коду: прочитай вихідний код додатка, щоб знайти захардкоджені креденшали, інші вразливості або вади бізнес-логіки
Вплив: Path traversal розкриває вихідний код, конфігураційні файли, креденшали, API-ключі, SSH-ключі та секрети оточення. У поєднанні з завантаженням файлів або ін'єкцією у логи може ескалюватися до Remote Code Execution. OWASP оцінює це як вразливість високої серйозності.
