Модуль 08 — Налаштування лабораторного середовища

Перш ніж почати хакати: підготовка середовища

Модулі з вразливостями в цьому курсі містять справжні вразливі вебзастосунки, які ти можеш зламувати локально на своїй машині. Кожна лабораторна — це Flask (Python) застосунок, упакований у Docker-контейнер. У цьому модулі ми покроково встановимо все необхідне.

Що потрібно встановити: Git (щоб клонувати репозиторій) та Docker + Docker Compose (щоб запускати лабораторні). Це все. Налаштовувати Python окремо не потрібно — Docker бере це на себе.

Крок 1: Встановлення Git

Git — це система контролю версій. Вона потрібна, щоб завантажити (клонувати) репозиторій курсу.

Windows

Завантаж і встанови Git for Windows з https://git-scm.com/download/win. Запусти інсталятор із налаштуваннями за замовчуванням. Після встановлення відкрий Git Bash або PowerShell і перевір:

git --version
# Should output something like: git version 2.43.0

macOS

Git входить до складу Xcode Command Line Tools. Відкрий термінал і виконай:

xcode-select --install
# Or install via Homebrew:
brew install git

git --version

Linux (Ubuntu/Debian)

sudo apt update && sudo apt install git -y
git --version

Крок 2: Встановлення Docker & Docker Compose

Docker запускає кожну лабораторну в ізольованому контейнері — як маленька віртуальна машина. Docker Compose дозволяє зібрати й запустити ці контейнери однією командою.

Windows & macOS

Встанови Docker Desktop з https://www.docker.com/products/docker-desktop/. Docker Desktop включає і Docker, і Docker Compose. Після встановлення переконайся, що Docker Desktop запущений (ти побачиш іконку кита в системному треї).

docker --version
# Should output: Docker version 24.x or newer

docker compose version
# Should output: Docker Compose version v2.x

Linux (Ubuntu/Debian)

# Install Docker
curl -fsSL https://get.docker.com | sh

# Add your user to the docker group (so you don't need sudo)
sudo usermod -aG docker $USER

# Log out and back in, then verify:
docker --version
docker compose version

Якщо docker compose не знайдено, можливо, потрібно встановити плагін Compose окремо:

sudo apt install docker-compose-plugin
Поширена проблема: Якщо ти отримуєш "permission denied" під час виконання команд Docker на Linux, переконайся, що ти додав свого користувача до групи docker і перелогінився. Або додавай sudo перед командами.

Крок 3: Клонування репозиторію

Відкрий термінал і клонуй репозиторій WebHack Academy: 

git clone https://github.com/morronel/client_web_hacking_path.git
cd client_web_hacking_path

Це завантажить весь курс, включаючи вихідний код усіх лабораторних. Лабораторні знаходяться в директорії labs/: 

ls labs/
# sqli/  xss/  ssti/  idor/  auth/  csrf/  ssrf/  traversal/
# cmdi/  xxe/  race/  deserial/  graphql/

Крок 4: Запуск лабораторної

Кожна лабораторна — це окремий Docker-контейнер. Щоб запустити одну з них: 

# Navigate to a lab directory
cd labs/sqli

# Build and start the container
docker compose up --build

# The lab is now running! Visit it in your browser:
# http://localhost:5001

Натисни Ctrl+C, щоб зупинити лабораторну, коли закінчиш.

Порада: Додай -d, щоб запустити у фоновому режимі: docker compose up --build -d. Потім використовуй docker compose down, щоб зупинити.

Корисні інструменти

Більшість завдань можна розв'язати лише за допомогою браузера та curl, але ці інструменти значно полегшать роботу:

  • curl — HTTP-клієнт командного рядка (є в Linux/Mac, на Windows встановлюється через Git Bash)
  • Burp Suite Community — перехоплює та модифікує HTTP-запити між браузером і лабораторною
  • Browser DevTools (F12) — вкладки Network, Console та Application для роботи з cookies
  • webhook.site — безкоштовний сервіс, що дає URL для отримання HTTP-колбеків (корисний для крадіжки cookies через XSS та тестування SSRF)
  • Python 3 — для написання експлойт-скриптів (автоматизація blind SQLi, генерація pickle-пейлоадів тощо)

Усунення неполадок

"Cannot connect to the Docker daemon"

Переконайся, що Docker Desktop запущений (Windows/Mac) або служба Docker працює (Linux):

# Linux
sudo systemctl start docker

"Port already in use"

Інша лабораторна (або програма) вже використовує цей порт. Спочатку зупини її:

docker compose down   # in the other lab's directory
# Or stop all containers:
docker stop $(docker ps -q)

"Build fails" або "pip install fails"

Лабораторні використовують попередньо зібрані wheel-файли для офлайн-встановлення, тому проблеми з мережею під час збірки не повинні виникати. Якщо збірка не вдалася, спробуй:

docker compose build --no-cache
Все готово! Коли Git і Docker встановлені, переходь до першого модуля з вразливостями (SQL Injection) і починай хакати. На сторінці кожного модуля є конкретна команда docker compose для запуску його лабораторної.
